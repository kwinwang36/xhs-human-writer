# xhs-human-writer

一个面向 Codex 的小红书中文写作 Skill。它把公开内容研究、研究门禁、原创写作、事实边界、真人感审校和个人声音沉淀拆成独立阶段，重点不是套用“爆款模板”，而是在不编造经历、不搬运参考帖的前提下完成可核验的原创内容。

## 它适合什么任务

当你只有一个选题，需要先研究同主题公开笔记；当你有事实、体验、链接或零碎表达，希望整理成小红书正文；当你已经有草稿，想检查 AI 腔、事实越界和参考来源重合；或当你明确批准一篇定稿，希望逐步形成个人声音档案时，可以调用这个 Skill。

## 安装

将仓库中的 `xhs-human-writer` 文件夹完整复制到 Codex 的 Skills 目录：

```bash
git clone https://github.com/kwinwang36/xhs-human-writer.git
cp -R xhs-human-writer/xhs-human-writer ~/.codex/skills/
```

重新打开 Codex 会话后，通过 `$xhs-human-writer` 调用。

## 使用示例

```text
$xhs-human-writer 根据这个选题执行完整研究和写作流程。

$xhs-human-writer 把这些真实经历整理成一篇小红书笔记，不要补造细节。

$xhs-human-writer 审查这篇草稿，重点检查 AI 腔、事实边界和参考来源重合。
```

## 工作方式

冷启动研究必须先确认研究任务书，再搜索、筛选和分析公开内容。第一次研究交付只包含研究报告；只有用户明确接受报告后，才进入正文写作。外部笔记只能提供主题地图、结构机制和语言温度，不能把他人的身份、经历、比喻、案例顺序或原句改写成自己的故事。

完成正文后，Skill 会依次检查事实与诚实、研究目的、真人感、来源独立性、表面 AI 痕迹和平台交付边界。个人声音档案只有在用户明确批准最终版本后才会更新。

## 仓库内容

`SKILL.md` 是主工作流；`references/` 包含样本筛选、研究报告、写作和审校规则；`scripts/source_overlap.py` 用于发现成稿与参考资料之间较长的精确文本重合；`agents/openai.yaml` 提供 Skill 的界面元数据。

## 重要边界

这个 Skill 不承诺内容“必爆”、规避 AI 检测或绕过平台规则。使用联网搜索或已登录账号时，应遵守平台当时有效的规则；未经明确授权，不应发布、评论、点赞、收藏、关注，也不应索取 Cookie 字符串或安装第三方采集器。
